03 · STATEMENT 3, POINT BY POINT
THE QUESTIONHOW WE ANSWER ITMONGODB UNDER IT

1Did it take effect, or was it only sent?

Every action gets a unique id in the ledger. The Guard reads the system back. “Done” but unchanged → ACK ≠ APPLIED, retry with a new attempt id.

  • multi-doc transactions
  • unique index = exactly once
  • pre-images custody trail ★

2Can it resume after a crash?

Agents hold leases with a generation number. A Nurse claims the expired lease; the old agent’s token is fenced off. Resume from the last verified step.

  • findOneAndUpdate leases + fencing
  • MongoDBSaver checkpoints
  • change streams + resume tokens
  • TTL indexes

3Can it adapt when fields change?

A schema check spots the rename. Claude proposes the mapping, the Guard checks it on real values, Atlas stores it by system version.

  • $jsonSchema validators
  • field-diff aggregation
  • $vectorSearch memory

+And it proves it got faster.

The learning curve and round-by-round times are computed in the database, not in the browser.

  • $setWindowFields ★
  • $percentile p50 / p90 ★
